# Post a Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verified .edu students can post, list, edit and delete their own room listings.

**Architecture:** Pure CommonJS modules (`lib/listingInput.js`, `lib/geocode.js`) hold the validation and Mapbox response parsing, so bare-node self-check scripts can test them, the same way `lib/searchFilters.js` works. Route handlers in `app/api/listings/**` gate on `getEduDbUser()` (lib/auth.ts), validate, geocode, and scope every write to `ownerId` in the Prisma `where`. Two new pages under `app/listings/` share one client form.

**Tech Stack:** Next.js 14 App Router, Prisma 5 + Supabase Postgres, Clerk 6, Mapbox Geocoding v6, Tailwind 3.

**Spec:** the user's brief in the session (2026-11-06), summarised in Global Constraints.

## Global Constraints

- Do not edit: app/page.tsx, components/SearchBar.tsx, scripts/validate-data.js, prisma/seed-data.json, prisma/seed.js, middleware.ts, app/layout.tsx.
- Schema change: only `clerkId String @unique` on User. `prisma db push` only after the user approves the printed diff. Never `npm run seed`.
- Money: integer USD, 0..10000, `rentShare <= totalRent`. Enums: roomType PRIVATE|SHARED, genderPref BROTHERS|SISTERS|ANY. baths in 0.5 steps. title ≤ 80, description ≤ 1000, address ≤ 200, all trimmed, unknown keys dropped.
- lat/lng come only from server-side geocoding, bbox = Southern California.
- `contactEmail` = signed-in user's verified email, `ownerId` = signed-in user. Never from the body.
- Status codes: 400 field errors, 403 not .edu, 404 missing or not owner, 422 address not found, 429 over 5 listings.
- UI: navy `ink` / gold `lantern` / `paper` tokens, 44px+ tap targets, mobile-first. Tailwind only scans `app/**`, so new components live under `app/listings/`.

## Review Focus

1. Numbers arrive as strings from form inputs ("1200", "", " 3 ") → accept numeric strings, reject empty and non-numeric with a field error. (Task 1 tests.)
2. Someone else's listing id on PATCH/DELETE → 404 and no change, enforced in the same query (`updateMany`/`deleteMany` with `{ id, ownerId }`). (Task 4 API check.)
3. Mapbox returns a feature outside the bbox or no features → null → 422. (Task 2 tests.)
4. Body is not JSON / is an array / has `ownerId`, `lat`, `contactEmail` keys → 400 or keys ignored. (Task 1 tests.)
5. A user whose primary email changes keeps the same User row (upsert by clerkId updates email). (Task 3.)

### Task 1: Listing validator

**Files:** Create `lib/listingInput.js`, `scripts/check-listing-input.js`

**Interfaces — Produces:** `validateListing(raw: unknown) => { ok: true, data: ListingFields } | { ok: false, errors: Record<string, string> }`; `ListingFields = { title, address, roomType, totalRoommates, beds, baths, totalRent, rentShare, avgUtilities, petsAllowed, halalKitchen, genderPref, description: string|null }`. Full-object validation (PATCH sends the whole form).

Ranges (my call): totalRoommates int 1–20, beds int 0–20, baths 0.5–10 in 0.5 steps, money int 0–10000. Booleans must be real booleans; missing booleans default false/true like the schema (pets false, halal true). Empty description → null.

- [ ] Implement `lib/listingInput.js`.

### Task 4: API routes

**Files:** Modify `app/api/listings/route.ts` (add POST only); create `app/api/listings/mine/route.ts` (GET), `app/api/listings/[id]/route.ts` (PATCH, DELETE).

- POST: user → 403; JSON → validate → 400 `{ error, fields }`; count ≥ 5 → 429; geocode null → 422 `{ fields: { address } }`; create with ownerId/contactEmail; 201 with listing.
- PATCH: validate full body; load `{ id, ownerId }` → 404; geocode only if trimmed address differs; `update`.
- DELETE: `deleteMany({ where: { id, ownerId } })`, count 0 → 404, else 204.
- shortcut: the 5-listing count is check-then-create, so two simultaneous posts can make a 6th; fine at this scale.
- [ ] Before code: write the API checks the browser run must pass (Task 6). Implement. tsc. Commit.
